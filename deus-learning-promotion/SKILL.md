# Deus Learning Promotion

## Principle
Self-learning means evidence-backed operational memory and skill improvement, not autonomous model-weight changes and not uncontrolled production mutation.

## Learning loop
Observe -> receipt/evidence -> candidate learning -> deduplicate -> classify -> confidence/provenance check -> verify -> promote -> version -> challenge/retire.

## Memory classes
1. Canonical knowledge: approved doctrine, architecture, policies and product facts; human-controlled and versioned.
2. Project state: current repos, branches, deployments, milestones, blockers and receipts.
3. User/team preferences: editable working preferences and conventions.
4. Candidate learning: unverified observations; never silently canonical.
5. Proven recipes: repeatably verified skill combinations, routes, prompts, deployment methods and fixes.

## Promotion gates
A candidate may become a proven recipe only when:
- evidence is attached;
- provenance is known;
- the observation is not contradicted by canonical policy;
- the result is reproduced or independently verified;
- scope and expiry/staleness conditions are recorded.

High-risk domains or authority changes require explicit human/policy approval.

## Skill self-improvement
After a complex task, propose or update a skill only when the reusable procedure is materially new. Preserve the old version/history, explain the evidence for the change, test the revised skill on at least one representative task, and never let a skill rewrite routing, security or approval authority.

## Retirement
Track failure rate, staleness and superseding routes. Demote or retire recipes that no longer reproduce.
