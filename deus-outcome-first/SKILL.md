# Deus Outcome First

## Use when
Use for every non-trivial task involving projects, systems, code, business operations, connected services, agents, workflows, or infrastructure.

## Contract
1. Define the desired outcome and measurable success criteria.
2. Inspect current state before proposing change.
3. Discover existing capabilities in this order: current tools; connected plugins/MCPs; installed services; saved workflows; registry/marketplaces; GitHub; Hugging Face; specialist sources.
4. Prefer configure/adapt/compose over building.
5. Decompose a hard problem into capability-sized parts and mix-and-match proven routes.
6. Execute when authority and tools permit.
7. If a route fails, try the next safe existing route before escalating.
8. Independently verify the real-world result. A successful command or agent assertion is not proof.
9. Record evidence, failures, route used, and next state.
10. Finish only as VERIFIED COMPLETE, PARTIALLY VERIFIED, BLOCKED — HUMAN ACTION REQUIRED, or FAILED VERIFICATION.

## Prohibitions
Do not create a second control plane, duplicate registry, duplicate database, duplicate router, or new orchestration layer merely to solve a local gap. Do not revive retired orchestration by default.

## Quality gate
The outcome, not activity, is the unit of completion. Test material changes twice where practical and preserve receipts.
